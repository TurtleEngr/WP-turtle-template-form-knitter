Turtle Template Form Knitter

ver-1.0.2

When a Contact Form 7 form is submitted, this plugin saves the uploaded image files to the Media Library. Then this plugin can create a "pending post" from a template post page. The first uploaded image is attached as the post's featured image

Install

  1. Install contact-form-7 plugin.
    • Rollback to version 6.1.7, if date fields don't work. For why see issue: https://github.com/TurtleEngr/WP-turtle-template-form-knitter/issues/1
    • Installing "WP Rollback" plugin is the easiest way to rollback the plugin.
  2. Install flamingo plugin.
  3. Optional: Install ninja-auto-post-expire plugin
  4. If save-cf7-file-uploads is installed, delete it. It is not compatible with this plugin.
  5. Install this plugin: turtle-template-form-knitter

Development Installs

Some of these are not stable versions.

  1. Follow the Installation steps 1 to 4 above.
  2. Go to: https://moria.whyayh.com/rel/released/software/own/WP-turtle-template-form-knitter
  3. Then download the turtle-template-form-knitter-VER.zip file you want.
  4. In WordPress, install with Upload Plugin.

Usage

To use this plugin, you need to add some things to your contact-forms-7 forms. See "Contact Form Settings" section.

Also, you need to create a template for your posts. See "Template Page" section.

Uploaded images are saved for every form, even without create_post. See "Uploaded Files" section.

If you installed ninja-auto-post-expire, the "Post" option needs to be set to "Yes" for the Post Expire Settings.

Contact Form Settings

In the contact form's "Additional Settings" tab, add these settings:

create_post: true
post_template: PageSlug
skip_mail: on
do_not_store: false

  • create_post - this turtle-template-form-knitter plugin option. If 'true' that activates this plugin

  • post_template - this turtle-template-form-knitter plugin option. This is the "slug-name" for a "page" that will be used as a template to generate a "Pending" post from a form. See "Template Page" for details.

  • skip_mail - contact-form-7 plugin option. This has no effect on the turtle-template-form-knitter plugin, but you can decide if you want to send an email of the form, in addition to making a post.

  • do_not_store - flamingo plugin option. The default is 'false'. If it is set to 'true', the form data will not be stored and this turtle-template-form-knitter plugin will not work.

This plugin does not "publish" the posts, but you should turn on reCAPTCHA in contact-form-7 settings so your admin doesn't get spammed with bot submitted "Pending" posts.

Template Page

All the blocks of the 'PageSlug' page are copied to the new post. {field} is replaced with the value of the form 'field' with that name. The field's HTML text is escaped. Also, "[" "]" is encoded so they cannot run a shortcode. Checkbox values are joined with ",". If there is no fields with that name, {field} is left as is.

Textarea fields are the exception: they can have some HTML. When HTML text is pasted into a form's textarea, it is cleaned, and the textarea shows the HTML tags that are kept. Only these tags are kept: h1, h2, h3, h4, a, p, b, strong, i, em, ul, ol, li, br. All attributes are removed, except href on "a" tags, and only for http, https, or mailto URLs. Other tags are removed (their text is kept), and script and style elements are removed with their content. The same cleaning is done again when the post is created. If a textarea value has none of the allowed tags, it is escaped like other fields.

So that the post can be edited in the block editor, a {field} with p, h1-h4, ul, or ol tags is changed to blocks: Paragraph, Heading, and List blocks. This only works when the {field} is in a Paragraph block in the template. Any text before or after the {field} in that paragraph is put in its own paragraph. In other blocks (for example a Heading), only the inline tags are kept, and the block tags are changed to line breaks.

A post's attributes are not blocks, so they are defined in the template between ATTR-BEGIN and ATTR-END lines, which are put after the Title. ATTR-BEGIN to ATTR-END and the text between them are not copied to the post; they are used to set the post's attributes. FYI, all of them are optional.

ATTR-BEGIN
title: {your-subject}
categories: {field}
tags: {field}
publish-date: {field}
expire-date: {field}
expire-time: {field}
ATTR-END
  • title - post title. See Flamingo documentation for how to change {your-subject} Default: UNDEFINED
  • categories, tags - comma separated names or slugs. Only existing categories and tags are used; others are ignored. Default: empty
  • publish-date - YYYY-MM-DD, time is set to 12:00. This date is kept when the post is published (a future date makes it "Scheduled"). Default: the time the post is published.
  • expire-date - YYYY-MM-DD. Saved in the ninja-auto-post-expire meta (_njtape_expiration_date). Default: not set.
  • expire-time - HH:MM. Default: 00:00

ninja-auto-post-expire only acts on posts if its "Post" option is set to "Yes" in it's settings, Post Expire Settings.

Invalid dates or times are ignored. An invalid expire-date is also shown in the error popup. See "Error Popup".

Uploaded Files

Files uploaded with the Contact Form 7 [file NAME] field are saved to the Media Library.

  1. Only image files are saved. The type is checked from the file content, and the file extension must also be an allowed image type. Other files are skipped and shown in the error popup.
  2. File names are normalized. File names can only contain letters in the set: [a-zA-Z0-9._-]. Any letters not in the set are converted to a "", and repeated "" are collapsed.
  3. Existing files are never overwritten. "_1", "_2", … is added to the base name instead.

If a post is created, the first saved image is the post's Featured Image.

Error Popup

Errors found while a form submission is processed are collected in memory.

When Contact Form 7 form is submitted any errors in turtle-template-form-knitter will be reported in a popup, usually a post will not be created. For example:

Turtle Template Form Knitter errors. Post not created.
To report, copy these errors now (they are not saved).


file type not allowed, not saved: photo.exe


invalid expire-date: "2026-13-01"

The popup is not shown if:

  • there were no errors.
  • JavaScript is turned off in the browser.
  • PHP stopped with a fatal error. Then the form does not get a reply at all.

These are all the possible errors. NAME is the uploaded file's name, PATH is where it was to be saved on the server.

  • Uploaded files. These can happen with any form, even without create_post. The other uploaded files are still saved.
    • file extension not allowed, not saved: NAME - the file extension is not an allowed image type.
    • file type not allowed, not saved: NAME - the file content is not an allowed image type.
    • copy failed, not saved: PATH - the file could not be copied to the uploads directory.
    • not added to Media Library, file removed: PATH: REASON - the file was copied, but could not be added to the Media Library.
  • Form settings and template. No post is made, except for the ATTR-END error.
    • post_template is not set for form ID - the form has create_post: true, but no post_template.
    • post_template page not found: SLUG - there is no page with that slug.
    • ATTR-END not found in the template - the template has an ATTR-BEGIN line with no ATTR-END line. The post is still made, but all the blocks after ATTR-BEGIN are left out.
  • Creating the post.
    • wp_insert_post failed: REASON - WordPress could not create the post.
    • invalid expire-date: "VALUE" - expire-date is not YYYY-MM-DD.
